# Lab 12 · Ping and Traceroute to Test Network Connectivity

## ภาพรวมของแล็บ

> 📌 อ้างอิง: **Packet Tracer 13.2.7 – Use Ping and Traceroute to Test Network Connectivity** (CCNA 1 v7)

**Objectives**
- **Part 1:** ทดสอบและกู้การเชื่อมต่อ **IPv4**
- **Part 2:** ทดสอบและกู้การเชื่อมต่อ **IPv6**

**Scenario:** เครือข่ายมีปัญหาการเชื่อมต่อ ให้รวบรวมและจดข้อมูล หาจุดผิด แล้วแก้ไข (แล็บให้รหัสผ่าน user EXEC และ privileged EXEC มา)

## 1. Addressing Table

**ภาพรวม:** router 3 ตัวต่อกันเป็นสาย **R1 — R2 — R3** ด้วยลิงก์ serial · ฝั่ง R1 มี PC1 (IPv4) และ PC2 (IPv6) · ฝั่ง R3 มี PC3 (IPv4) และ PC4 (IPv6)

```text
 PC1 (v4) ─ G0/1 ┐                                   ┌ G0/1 ─ PC3 (v4)
                 [R1] S0/0/1 ── S0/0/0 [R2] S0/0/1 ── S0/0/1 [R3]
 PC2 (v6) ─ G0/0 ┘   10.10.1.4/30          10.10.1.8/30      └ G0/0 ─ PC4 (v6)
```

## 2. Part 1: Test and Restore IPv4 Connectivity

**ขั้นตอน**
1. **รวบรวมข้อมูล:** `ipconfig /all` ที่ PC1 และ PC3 เติมตาราง แล้ว ping PC3 (10.10.1.18) จาก PC1 → **ไม่ผ่าน**
2. **หาจุดผิด:** `tracert` จาก PC1 → PC3 และ PC3 → PC1 · ดู R1 และ R3 ด้วย `show ip interface brief` และ `show ip route` · จด IP ของ R2
3. **เสนอวิธีแก้:** เทียบกับเอกสาร
4. **ลงมือแก้:** แก้ config ที่ **R2**
5. **ตรวจ:** ping ทั้งสองทิศ
6. **จดบันทึก**

**คำถามและคำตอบ (ตามแล็บ)**
| Step | คำถาม | คำตอบ |
|---|---|---|
| 2a | IPv4 สุดท้ายที่ trace จาก PC1 ไปถึง | **10.10.1.97** (R1 G0/1) |
| 2c | IPv4 สุดท้ายที่ trace จาก PC3 ไปถึง | **10.10.1.17** (R3 G0/1) |
| 2f | IPv4 ตัวที่สองของ R1 | **10.10.1.6** (S0/0/1) |
| 2g | เครือข่ายที่ต่อกับ R1 S0/0/1 | **10.10.1.6/32 และ 10.10.1.4/30** |
| 2h | R3 | S0/0/1 = 10.10.1.10, connected network = **10.10.1.8/30**, local host route = **10.10.1.10/32** |
| 2j | IP ของ R2 | **10.10.1.2** (S0/0/0) และ 10.10.1.9 (S0/0/1) |
| 3a | จุดผิด | **R2 S0/0/0 ตั้ง IP ผิด** |
| 3b | วิธีแก้ | ตั้ง R2 S0/0/0 = **10.10.1.5/30** |
| 5 | แก้แล้วหายไหม | **ใช่** |

> ⭐ **ทำไม 10.10.1.2 ผิด:** ลิงก์ R1–R2 คือวง **10.10.1.4/30** (ช่วง .4–.7) แต่ R2 ตั้ง **.2** ซึ่งอยู่วง 10.10.1.0/30 → R1 กับ R2 อยู่คนละวง คุยกันไม่ได้ trace จึงหยุดที่ router ตัวแรก

**คำสั่งแก้ (คำสั่งมาตรฐาน IOS)**
```text
R2(config)# interface s0/0/0
R2(config-if)# ip address 10.10.1.5 255.255.255.252
```

## 3. Part 2: Test and Restore IPv6 Connectivity

**ขั้นตอน**
1. **รวบรวมข้อมูล:** `ipv6config /all` ที่ PC2 และ PC4 (เขียนตามแล็บ) เติมตาราง แล้ว ping PC4 จาก PC2 → **ไม่ผ่าน**
2. **หาจุดผิด:** `tracert` จาก PC2 → PC4 และ PC4 → PC2 · ดู R3 ด้วย `show ipv6 interface brief`
3. **เสนอวิธีแก้** → 4. **แก้ที่ PC4** → 5. **ping ทั้งสองทิศ** → 6. **จดบันทึก**

**คำถามและคำตอบ (ตามแล็บ)**
| Step | คำถาม | คำตอบ |
|---|---|---|
| 2a | IPv6 สุดท้ายที่ trace จาก PC2 ไปถึง | **2001:db8:1:3::2** (R3 S0/0/1) |
| 2c | IPv6 สุดท้ายที่ trace จาก PC4 ไปถึง | **ไม่ถึง IPv6 address ใดเลย** |
| 2f | R3 มีจุดที่ไม่ตรงกันไหม | **มี** |
| 3a | จุดผิด | **PC4 ตั้ง default gateway ผิด** |
| 3b | วิธีแก้ | ตั้ง IPv6 gateway ของ PC4 = **fe80::3** (link-local ของ R3) |
| 5 | แก้แล้วหายไหม | **ใช่** |

> ⭐ อ่านอาการ: จาก PC2 ไปได้ถึง R3 (แปลว่าเส้นทางระหว่าง router ปกติ) แต่จาก PC4 **ไม่ถึงแม้แต่ hop แรก** → ปัญหาอยู่ที่ตัว PC4 เอง = gateway ผิด

## 4. คำสั่งและการอ่านผล

| คำสั่ง | ใช้ทำอะไร | อ่านผลอย่างไร |
|---|---|---|
| `ipconfig /all` / `ipv6config /all` | ดู address, mask/prefix, gateway ของ PC | เทียบกับเอกสาร หาค่าที่ตั้งผิด |
| `ping` | ทดสอบว่าถึงปลายทางไหม | ไม่ผ่าน = มีจุดเสียระหว่างทาง แต่ **ไม่บอกว่าตรงไหน** |
| `tracert` (PC/Windows) / `traceroute` (Cisco/Linux) | แสดงทุก hop ระหว่างทาง | **hop สุดท้ายที่ตอบ = จุดก่อนเส้นทางขาด** · "Request timed out." ซ้ำๆ หลังจากนั้น = ไม่มีคำตอบกลับจากข้างหน้า |
| `show ip interface brief` | IP และสถานะทุก interface | ต้อง **up/up** และ IP ตรงตาราง · "administratively down" = ถูก shutdown |
| `show ip route` | เครือข่ายที่ router รู้จัก | **C** = connected, **L** = local (IP ของตัวเอง /32) · ถ้าไม่มีวงไหน = ไปวงนั้นไม่ได้ |
| `show ipv6 interface brief` | IPv6 (global + link-local) ทุก interface | ไม่ตรงเอกสาร = config ผิด |
| **Ctrl+C** | หยุด trace | ไม่ต้องรอครบ 30 hops |

## จุดที่มักสับสน

| เรื่อง | A | B | จำง่ายๆ |
|---|---|---|---|
| ping vs tracert | บอกแค่ **ถึง/ไม่ถึง** | บอก **ไปถึงไหนแล้วขาด** | ping = ประตูเปิดไหม · tracert = แผนที่ทางเดิน |
| tracert vs traceroute | คำสั่งบน **Windows / PC ใน PT** | คำสั่งบน **Cisco IOS / Linux** | ทำงานเหมือนกัน |
| route C vs L | **C** = วงที่ต่ออยู่ (เช่น 10.10.1.4/30) | **L** = IP ของ interface ตัวเอง (/32) | L = Local host route |
| ปัญหาที่ router vs ที่ host | trace ไปได้บางส่วนแล้วหยุดกลางทาง | trace ไม่ถึงแม้ hop แรก | ไม่ถึง hop แรก = ดู gateway ของ PC ก่อน |

## จุดเน้นสำหรับสอบ
- 🔥 ใช้ **tracert หา hop สุดท้ายที่ตอบ** แล้วไปตรวจอุปกรณ์ถัดจากจุดนั้น
- 🔥 IPv4 fault: **R2 S0/0/0 = 10.10.1.2 (ผิดวง) → แก้เป็น 10.10.1.5/30**
- 🔥 IPv6 fault: **PC4 gateway ผิด → แก้เป็น fe80::3**
- ⭐ ตรวจว่าทุก interface อยู่ใน subnet ที่ถูก · gateway ของ host = router interface ใน LAN ตัวเอง
- ⭐ /27 = .224, /28 = .240, /30 = .252 · ลิงก์ /30 ใช้ได้ 2 IP
- ⭐ `show ip route`: C = connected, L = local
